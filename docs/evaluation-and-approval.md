# Agent / Skill 评估与发布门禁

本仓库是跨项目 Agent 与 Skill 的候选中心。任何从业务仓迁移到公共目录的 Agent/Skill，都必须先经过评估，再进入人工确认，确认后才允许发布。

## 评估维度

每项按 1–5 分评分：

| 维度 | 重点 |
|---|---|
| 直接价值 | 是否能减少当前项目开发、测试、发布或运维工作 |
| 跨项目复用 | 是否至少服务两个项目，或属于平台级能力 |
| 成熟度 | 是否有稳定输入输出、示例、测试和维护记录 |
| 重复度 | 与现有 Skill/Agent 的重叠程度；重复越多分越低 |
| 安全性 | 是否涉及密钥、生产写入、儿童数据、交易下单或高权限操作 |
| 迁移成本 | 路由、依赖、文档、配置和验证成本 |

建议总分 = 直接价值 + 跨项目复用 + 成熟度 + 安全性 + 迁移成本 + (6 - 重复度)，满分 30。

## 决策等级

- **P0 / 建议迁移**：总分 >= 24，边界清晰，有明确复用价值。
- **P1 / 合并后迁移**：总分 18–23，需要去重、拆分或补测试。
- **P2 / 项目私有**：总分 < 18，或包含强项目耦合、敏感策略、生产凭据。
- **Hold / 暂缓**：安全、许可、维护状态或来源无法确认。

## 发布流程

1. 扫描项目设计文档、AGENTS.md、现有 Skills/Agents、构建和 CI 配置。
2. 形成候选清单，标注来源、目标路径、评分、重复关系、风险和验证命令。
3. 只生成 proposal，不覆盖项目本地内容，不删除源文件。
4. 用户确认候选范围。
5. 将确认项迁移到 canonical 目录，修复路径、frontmatter、引用和测试。
6. 运行结构校验、冲突检查、敏感信息扫描和项目同步验证。
7. 通过后再提交到 `aihome-agent`；业务仓只保留 manifest/profile 和必要的项目扩展。
8. 下次更新必须生成版本差异和回滚点。

## 当前边界
